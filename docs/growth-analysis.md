# GrowthLens 增长分析口径

## 分析粒度

- 一行代表一个小程序用户；
- `user_id` 是唯一业务键；
- 所有时间均按业务本地时间解释；
- 上传文件只在单次请求内处理，不落库。

## 字段要求

核心字段必须能够映射为 `user_id`、`channel`、`register_time` 和
`order_amount`。`view_time`、`lead_time`、`appointment_time`、
`visit_time`、`pay_time` 为可选漏斗字段；缺失项会记录在
`schema_mapping.missing_fields` 与 `data_ingestion.missing_fields` 中，
但不会阻断分析。

## 清洗规则

1. 空用户 ID 的记录删除；
2. 重复用户优先保留必填字段最完整的记录，完整度相同时保留先出现的记录；
3. 渠道去除前后空格，空渠道归类为“未知”；
4. 时间统一转换为日期时间类型；
5. 无法解析、晚于当前时间一天以上、跳过前置步骤或早于前序步骤的时间视为异常，并从异常步骤起停止漏斗计数；
6. 空金额按 `0` 处理，非法或负金额修正为 `0`；
7. 文件提供了支付时间字段时，没有有效支付时间却存在正金额会将金额修正为
   `0`；文件未提供支付时间字段时，以正订单金额识别成交。

`anomaly_count` 表示至少命中一项质量规则的原始行数，各规则明细见
`issue_counts`。同一行可命中多项规则，因此明细之和不一定等于异常行数。

`data_completeness` 只评估业务必填信息，不把正常漏斗流失当成数据缺失：

- 所有有效用户：用户 ID、渠道、注册时间；
- 成交用户额外检查：订单金额是否大于 `0`。

## 指标口径

基础用户数按文件中实际存在的漏斗阶段逐级统计，保证展示出的漏斗人数单调
递减。缺失的可选阶段不会出现在 `funnel.stages` 中：

1. 注册用户数：存在有效注册时间；
2. 浏览用户数：已注册且存在有效浏览时间；
3. 留资用户数：已浏览且存在有效留资时间；
4. 预约用户数：已留资且存在有效预约时间；
5. 到店用户数：已预约且存在有效到店时间；
6. 成交用户数：存在支付时间时按有效支付时间统计，否则按正订单金额统计。

转化率均为相邻可用环节转化；完整模板仍保持以下原有口径：

- 浏览率 = 浏览用户数 / 注册用户数；
- 留资率 = 留资用户数 / 浏览用户数；
- 预约率 = 预约用户数 / 留资用户数；
- 到店率 = 到店用户数 / 预约用户数；
- 成交率 = 成交用户数 / 到店用户数。

收入指标：

- GMV = 成交用户有效订单金额之和；
- 客单价 = GMV / 成交用户数。

渠道分析使用相同口径分别计算，保证 Dashboard 总览与渠道视图可以复用同一结构。
